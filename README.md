# Аналитик цепочек и кластеров договоров

Автономный агент для пакета договоров и дополнительных соглашений. Он:

- читает PDF с текстовым слоем, сканы, смешанные PDF и DOCX;
- собирает цепочки «договор → дополнительные соглашения»;
- сворачивает условия, действующие на заданную дату;
- группирует договоры в кластеры и сравнивает их внутри кластера;
- пишет отчёт в Markdown и базу знаний для чата.

Значение попадает в отчёт и базу знаний только с дословной цитатой и номером страницы. Сомнительное или противоречивое значение агент не записывает, а выносит в раздел отказов с причиной.

Всё работает локально: модель — через Ollama, распознавание сканов — PaddleOCR PP-OCRv5 через RapidOCR (ONNX), ориентация страниц — Tesseract. Документы не уходят во внешние сервисы, трассировка LangSmith принудительно выключена.

## Установка

1. Python 3.12 и [uv](https://docs.astral.sh/uv/):

   ```bash
   curl -LsSf https://astral.sh/uv/install.sh | sh
   ```

2. Tesseract с русским языком: определяет ориентацию страниц сканов и служит запасным движком OCR. Сам текст сканов распознаёт RapidOCR, он ставится вместе с зависимостями.

   macOS:

   ```bash
   brew install tesseract tesseract-lang
   ```

   Linux:

   ```bash
   sudo apt install tesseract-ocr tesseract-ocr-rus
   ```

3. Зависимости проекта:

   ```bash
   uv sync
   ```

4. [Ollama](https://ollama.com) и модель:

   ```bash
   ollama pull qwen3:8b
   ```

   Модель не зашита в код: её выбирает тот, кто запускает агента, — `--model ollama:<модель>` или `llm_model` в `config/default.yaml`. По умолчанию `qwen3:8b`: она помещается в 16 ГБ вместе с OCR и укладывается по скорости. Сравнить модели на своём эталоне можно одной командой — `experiment e2 --models ollama:<a>,ollama:<b>`. Нужно около 6 ГБ памяти. На слабом железе подойдёт `qwen3:4b`: передайте `--model ollama:qwen3:4b`. Адрес Ollama задаётся в `CA_OLLAMA_URL`; адрес не на этой машине агент примет только с `CA_ALLOW_REMOTE_LLM=1`, потому что тексты документов уйдут на тот сервер.

### Модель на сервере заказчика

Кроме Ollama агент работает с любым сервером с OpenAI-совместимым API (vLLM, LM Studio, llama.cpp server):

```bash
CA_OPENAI_BASE_URL=http://localhost:8000/v1 uv run contract-analyst analyze <папка> --model openai:<имя модели на сервере>
```

Ключ, если сервер его требует, — в `CA_OPENAI_API_KEY` (в файлы не записывается). У моделей с рассуждениями (Qwen3) рассуждение для извлечения нужно выключить полем запроса в `openai_extra_body`: для vLLM — `{chat_template_kwargs: {enable_thinking: false}}`, для OpenAI-совместимого адреса Ollama — `{reasoning_effort: none}`; иначе модель тратит весь лимит токенов на рассуждение, и шлюз отказывается от значений. Сервер не на этой машине принимается только с `CA_ALLOW_REMOTE_LLM=1`: тексты договоров уходят на него, поэтому решение должно быть явным. Публичные облачные API для коммерческих документов не предполагаются; замеры с облачной моделью в `docs/experiments/final.md` сделаны на тестовых документах задания.

## Быстрый старт без модели

В репозитории лежит отложенный синтетический набор `synthetic/build`. Это три вымышленные цепочки: аренда со сканом основного договора, услуги в DOCX с расторжением и дилерский договор с отменённым соглашением. К набору записан кэш ответов модели, поэтому запуск в режиме `replay` не требует Ollama. Ключ кэша — запрос вместе с параметрами генерации (лимиты токенов, контекст, сэмплинг, `openai_extra_body`), а ответ, оборванный на лимите токенов, не записывается: после смены параметров модель спрашивается заново.

```bash
uv run contract-analyst analyze synthetic/build --as-of 2026-10-30 --llm-cache replay --cache-file synthetic/llm_cache.sqlite
```

## Пример запроса и ожидаемого ответа

Запуск на синтетическом наборе:

```bash
uv run contract-analyst analyze synthetic/build --as-of 2026-10-30
```

Команда печатает пути к результатам. В `runs/<время>-B/` появятся:

| Файл | Что внутри |
|---|---|
| `report.md` | отчёт: сводка, опись, кластеры, договоры (цепочка, эволюция условий, действующие условия), отказы и противоречия, необработанное, Reflection, трасса и метрики |
| `kb/` | база знаний для чата |
| `trace.jsonl` | мысли агента, вызовы инструментов, ошибки |
| `metrics.json` | время и число вызовов модели |

Фрагмент `report.md` для договора аренды (повтор из записанного кэша; живая модель может сформулировать условия иначе): в разделе «Действующие условия на 2026-10-30» ставка берётся из первого дополнительного соглашения, а срок — из второго.

```markdown
| Условие | Значение | Источник |
|---|---|---|
| Срок действия | действует до 31.12.2026 с автоматической пролонгацией на год | [doc:3130ea621d4d:p1] |
| Ставка «арендная плата» | 120 000 руб. без НДС с 2025-04-01 | [doc:d566d8a87702:p1] |
```

Чат по базе знаний этого запуска:

```bash
uv run contract-analyst chat runs/<время>-B/kb
```

> **Вопрос:** Какая арендная плата действует на 30.10.2026 по договору аренды D990100001-01?
>
> **Ожидаемый ответ** (так ответила `qwen3:8b` при оценке чата; формулировка зависит от модели, проверяются сумма, НДС и ссылка): Арендная плата по договору D990100001-01 на 30.10.2026 составляет 120 000 руб. без НДС [doc:d566d8a87702:p1].

На вопрос, ответа на который в документах нет, чат должен ответить «Нет данных в базе знаний.» (с `qwen3:8b` — не всегда, см. «Ограничения»). Чат помнит диалог, поэтому уточнение «А срок аренды по нему продлевали?» относится к тому же договору. Каждый запуск `chat` начинает новый диалог и печатает его номер; продолжить прежний — `--thread <номер>`.

## Свои документы

Положите файлы в папку (вложенные папки допустимы) и запустите:

```bash
uv run contract-analyst analyze <папка> --as-of 2026-10-30
```

Архив из задания распакуйте скриптом, который восстанавливает русские имена файлов (кодировка CP866):

```bash
uv run python scripts/extract_archive.py Задание_выборка.zip data/raw
```

Папка `data/` не попадает в git: документы, эталон и кэши остаются на машине.

## Команды

| Команда | Что делает |
|---|---|
| `analyze <папка>` | полный разбор. Опции: `--as-of` — дата свёртки; `--chain <номер>` — только одна цепочка; `--doc <файл>` — только один файл; `--model`; `--variant A\|B\|C`; `--llm-cache record\|replay\|off`; `--cache-file`; `--out` |
| `chat <kb> [--thread <номер>]` | вопросы по базе знаний с памятью диалога; без `--thread` — новый диалог |
| `eval golden <run>` | сравнить прогон с эталоном: метрики, ловушки, причины промахов свёртки и свёртка эталонных значений |
| `eval chat <kb>` | оценить ответы чата: факты, отказы, ссылки |
| `experiment e2\|e3\|e4` | замеры моделей, способа свёртки и оркестрации |
| `golden prefill\|dump-texts\|diff\|check\|review` | инструменты разметки эталона |

Все команды запускаются как `uv run contract-analyst <команда>`, справка — `--help`.

## Проверка

```bash
uv run pytest -m "not real and not ollama"
```

Тесты с меткой `real` требуют `data/raw` и `data/golden`, с меткой `ollama` — запущенную модель. Честная оценка на документах, по которым ничего не настраивалось, — отложенный набор `holdout/` (собирается `scripts/make_holdout.py`):

```bash
uv run contract-analyst analyze holdout/build --as-of 2026-10-30 --out runs/holdout
```

```bash
uv run contract-analyst eval golden runs/holdout/<прогон> --golden holdout/golden.yaml
```

Тот же набор проверок, что и в CI, в чистом Ubuntu-контейнере:

```bash
bash scripts/ci_local.sh
```

## Как устроено

Коротко: код читает файлы, распознаёт сканы, разбирает заголовки, собирает цепочки и сворачивает условия. Модель извлекает условия из текста. Агент решает исключения: перечитать плохой скан, разобрать противоречие, решить, что работа закончена. Каждое значение проходит шлюз проверок: цитата есть на странице, значение следует из цитаты, формат верный, OCR уверен.

Подробнее — в `docs/architecture.md`. Почему выбраны RapidOCR, свёртка кодом и гибридная оркестрация — в `docs/experiments/`: каждый выбор сделан замером по правилу, записанному до замера. Модель — параметр запуска, её выбирает заказчик.

## Структура

```
src/contract_analyst/
  ingest/  ocr/  parsing/     чтение, распознавание, регулярные разборы
  understand/  gate/          извлечение моделью и проверки значений
  assemble/  analyze/         цепочки, свёртка, кластеры
  agent/  chat/  kb/  llm/    граф агента, чат, база знаний, клиент модели
  report/  eval/              отчёт, эталон и метрики
prompts/                      промпты с версиями (_vN)
config/default.yaml           параметры и победители замеров
synthetic/                    отложенный синтетический набор с эталоном
tests/                        юнит, агент на записанных ответах, ошибки, e2e
docs/                         архитектура, замеры, инструкция разметчика
```

## Ограничения

- Скорость: на Apple M4 с 16 ГБ `qwen3:8b` читает вход примерно со скоростью 130 токенов/с и пишет примерно 13,5 токена/с (замер через Ollama, контекст 16 384). Пакет задания — около 125 вызовов модели; прогон, в котором 61 вызов шёл без кэша, занял 1 ч 45 мин, полностью без кэша — порядка 3 часов (оценка по той же скорости). Больше всего времени уходит на ответ модели: JSON с дословными цитатами, по которым шлюз проверяет значения, и долгие договоры на 66–75 страниц. 9 коротких синтетических документов — около 25 минут; облачная модель через OpenAI-совместимый API — минуты (отложенный набор — 3,5 мин). Повтор из кэша — секунды.
- Точность — `docs/experiments/final.md`. Требование «ноль принятых неверных значений» на реальных и на отложенных данных не выполнено: шлюз отсекает значения, которых нет в тексте, но не все ошибки роли (настоящее число из документа, отнесённое не к тому полю).
- Чат с `qwen3:8b` полностью верно отвечает на 2 из 15 вопросов по реальному пакету и на 1 из 8 по синтетике: часто отказывается, хотя ответ в базе есть, и пересказывает ошибки базы. Ссылку на источник даёт в каждом фактическом ответе — по ней ответ и нужно проверять (`docs/experiments/final.md`, раздел «Чат»).
- Рукописные пометки не распознаются. Значения со страниц с низкой уверенностью OCR агент отклоняет, а не угадывает.
- Номер документа ищется по шаблону `D` + 9 цифр + `-NN` (`parsing/patterns.py`). Другую нумерацию нужно добавить в шаблон.
- Только русский язык.
- PyMuPDF распространяется под AGPL-3.0. Для закрытого коммерческого использования нужна коммерческая лицензия либо замена на pypdfium2 (Apache-2.0).
