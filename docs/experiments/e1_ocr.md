# E1 — выбор OCR-движка по замеру

Прогон: 2026-11-01 03:00, длительность 15.8 мин. Команда: `uv run python -m contract_analyst.eval.ocr_bench --data data/raw --out docs/experiments/e1_ocr.md`.
Документ содержит только метрики: ни текстов, ни номеров, ни имён файлов (документы конфиденциальны).

## Варианты

Tesseract 5 (`rus`) и PaddleOCR PP-OCRv5 eslav через RapidOCR/ONNX, каждый без предобработки (`none`) и с выравниванием и бинаризацией Sauvola (`deskew_sauvola`). Не сравнивались (спека §7.2): EasyOCR — тянет PyTorch и медленный на CPU; VLM-читатель — не используется. Облачный OCR исключён: документы не покидают машину.

## Правило выбора (записано до замера: спека §7.2, план Task 18)

1. Максимум покрытия критичных токенов при пороге уверенности, дающем точность принятых ≥ 0.99 (`crit_coverage_at_p99`).
2. При ничьей (разница ≤ 0.01) — меньший CER.
3. Затем — меньшее время на страницу.

Критичный токен — слово (без знаков препинания по краям), целиком совпадающее с номером документа (`D\d{9}(-\d{2})?`) или числом (`\d[\d.,]*\d|\d`): даты, суммы, номера пунктов. Искажённое слово (например, номер с кириллической «Д») токеном не считается: разборщики не примут его за значение, поэтому оно снижает покрытие, а не точность. Токен OCR принят, если уверенность его слова ≥ t (у RapidOCR уверенность — по строке). Точность(t) — доля принятых токенов, которые есть среди критичных токенов эталона той же страницы (сопоставление мультимножеств: каждый токен эталона засчитывается не больше одного раза). Покрытие(t) — верно принятые токены / все критичные токены эталона. Обе величины считаются по всем страницам сразу. Порог t — наименьший на сетке 0.50…0.99 (шаг 0.01), при котором точность ≥ 0.99; если такого нет, покрытие = 0. Порог в конфиг = min(t + 0.05, 0.99) — запас по §6.14.

## Наблюдения

- Номера документов `D…` со сканов плохо читают все варианты: точно прочитано не больше 27% номеров даже без порога уверенности. Искажённое слово не похоже на номер, поэтому разборщики его не примут: номер со скана будет `absent`, а не неверным. Это задача нормализации после OCR, а не выбора движка.
- `tesseract` + `none`: при пороге в конфиг 0.99 не принимается ни один критичный токен (при t = 0.97 покрытие 0.002): уверенность слов этого движка до порога с запасом не доходит.
- `tesseract` + `deskew_sauvola`: точность 0.99 не достигается ни при каком пороге; лучшая — 0.989 при t = 0.96.
- `rapidocr` + `deskew_sauvola`: запас +0.05 снижает покрытие с 0.717 до 0.158.
- `rapidocr` + `none`: WER 0.329, а без учёта порядка слов — 0.199. Большая часть ошибок — порядок, в котором склеены строки, а не распознавание слов; он портит CER и мешает шлюзу найти цитату, которая переходит через строку.
- `rapidocr` + `deskew_sauvola`: WER 0.362, а без учёта порядка слов — 0.216. Большая часть ошибок — порядок, в котором склеены строки, а не распознавание слов; он портит CER и мешает шлюзу найти цитату, которая переходит через строку.
- `rapidocr` + `none`: `ocr_page` вернул в нормальное положение 0% страниц, повёрнутых на 90°; CER на этих страницах 0.733 при среднем 0.258.
- `rapidocr` + `deskew_sauvola`: `ocr_page` вернул в нормальное положение 0% страниц, повёрнутых на 90°; CER на этих страницах 0.732 при среднем 0.291.

## Когда пересмотреть выбор

- Появились расшифровки реальных сканов (Task 17): та же команда добавит их метрики. Если на реальных страницах варианты расположатся иначе, выбор обсуждается заново: правило для такого расхождения заранее не записано.
- Исправлены автоповорот или порядок строк, добавлена нормализация номеров документов после OCR: замер повторяется с тем же seed (те же страницы и деградации), порог пересчитывается.
- Другая машина или ОС: время на страницу нужно перемерить. На выбор оно влияет только при ничьей по правилам 1–2.

## Данные и условия прогона

- Синтетические сканы: 40 страниц из 14 PDF с текстовым слоем; seed = 0. Страницы выбраны случайно, по кругу между документами. Страницы, где картинки занимают больше 1% площади, исключены: их содержимого нет в текстовом слое. Мелкие картинки (логотипы) закрашены белым.
- Рендер 200 dpi. Деградации: поворот на 90° у 10 из 40 страниц (25%), перекос ±3°, размытие σ ∈ [0, 1.2], шум σ ∈ [0, 12], JPEG с качеством 40–90, масштаб 0.6–1. Уменьшенная страница возвращается к размеру 200 dpi: так читатель растрирует скан низкого разрешения при фиксированном dpi.
- Эталон — текстовый слой страницы после `normalize_text`; текст OCR нормализуется так же. CER и WER — `eval.text_metrics` (переводы строк не считаются), по всем страницам с весом длины эталона.
- Распознавание — `ocr_page`, как в читателе: с автоповоротом и выбранной предобработкой. Время — среднее на страницу после прогрева модели. Варианты чередуются постранично: каждая страница проходит все варианты, и первый вариант каждый раз сдвигается. Поэтому изменение загрузки машины влияет на все варианты одинаково. Средняя загрузка (load average за 1 мин) во время замера: 7.5–8.4 по вариантам.
- Реальных страниц-сканов с расшифровкой: 0.
- Машина: Darwin 24.6.0 arm64, 10 CPU, Python 3.12.12; load average 1/5/15 мин в начале прогона: 3.7 / 7.2 / 13.7.
- Движки: Tesseract 5.5.2 (`rus`, `--psm 6`), pytesseract 0.3.13; RapidOCR 3.10.0 (PP-OCRv5 mobile: det + eslav rec), onnxruntime 1.31.1.
- Библиотеки: OpenCV 5.0.0, PyMuPDF 2.0, NumPy 2.5.4.
- Вес моделей (справочно, критерий 3 спеки): RapidOCR — модели 12.7 МБ + onnxruntime; Tesseract — `rus.traineddata` 3.7 МБ + бинарник (системный пакет).
