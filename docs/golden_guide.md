# Инструкция по разметке эталона

Эталон — заранее записанные правильные ответы. Агент запускается на тех же документах, а скрипт сравнивает его ответы с эталоном. От точности эталона зависят все замеры, поэтому главное правило — **у каждого значения есть дословная цитата и номер страницы**.

Схема — `src/contract_analyst/eval/golden.py` (`GoldenSet`). Формат файла — YAML.

## Исходные материалы

- `data/golden/texts/<doc_id>.txt` — текст документа по страницам: `=== PAGE N (text|ocr|empty) ===`.
- `data/golden/texts/png/<doc_id>_pN.png` — изображения страниц-сканов, для сверки и расшифровки.
- `data/golden/prefill.yaml` — заготовка: номера, даты, город и ссылки из заголовков, найденные регулярными выражениями. Заготовку нужно проверить, а не принять на веру.

## Общие правила

1. `quote` — дословная копия фрагмента из текстового файла: те же слова, цифры и кавычки, 5–40 слов. Для страниц-сканов цитата берётся из текста OCR, если он читается; если OCR испорчен — из изображения, и тогда значение получает `status: rejected` с пояснением в `quote`.
2. `page` — номер страницы из маркера `=== PAGE N`.
3. Даты — `YYYY-MM-DD`. Суммы — как в тексте, десятичная запятая допустима (`"330,5"`).
4. Статусы значения:
   - `accepted` — значение есть в тексте;
   - `redacted` — значение вымарано (прочерки, подчёркивания, пустые кавычки), `value: null`;
   - `absent` — значения в документе нет, `value: null`, `page` и `quote` не нужны.
5. Ничего не выводить из имени файла или папки: только из текста документа.
6. Если документ противоречит сам себе (например, заголовок и текст называют его по-разному), в значении пишется то, что следует из содержания, а противоречие фиксируется ловушкой (раздел «Ловушки»).

## Документы (`documents`)

| Поле | Что писать |
|---|---|
| `file` | путь из `prefill.yaml` |
| `doc_id` | из `prefill.yaml` |
| `kind` | `main` — основной договор; `supplement` — изменяет или дополняет другой документ; `framework` — самостоятельное соглашение поверх других договоров, не меняющее их текст; `unknown` |
| `is_draft` | `true`, если документ помечен как проект |
| `number`, `doc_date`, `city` | реквизиты самого документа |
| `parent_number`, `parent_date` | номер и дата документа, на который ссылается этот, **как они написаны в тексте** |
| `effective_from` | дата вступления в силу или дата, с которой документ распространяет действие; если «с момента подписания», а даты подписания нет — `absent` |
| `subject_category` | ключ из `config/default.yaml` → `subject_categories` |
| `counterparty_type` | `ИП`, `ООО`, `АО` и т. п. или `redacted` |
| `terms` | ключи из групп `core_terms` и `dealer` в `config/default.yaml`; значение — условие словами документа, коротко |
| `rates` | по записи на каждую сумму и период: `label`, `amount`, `vat` (`included`/`excluded`/`unknown`), `valid_from`, `valid_to`, `page`, `quote` (сумма входит в цитату) |
| `ops` | операции изменения: `op`, `target`, `effective_from`, `page`, `quote` |

Виды операций: `replace_clause` (пункт в новой редакции, `target` — номер пункта), `add_clause`, `delete_clause`, `restate_document` (весь документ в новой редакции), `restate_section` (раздел или группа пунктов, `target` — например `1-8`), `replace_appendix` (`target` — например `Приложение 7`), `terminate` (расторжение целиком), `suspend_part` (прекращение части обязательств при сохранении договора), `invalidate_document` (отмена ранее подписанного документа, `target` — его номер), `other`.

## Цепочки (`chains`)

| Поле | Что писать |
|---|---|
| `contract_number` | номер основного договора (или номер, на который ссылаются соглашения, если договора в пакете нет) |
| `main_doc_id` | `doc_id` основного текста или `null` |
| `order` | все `doc_id` цепочки по дате вступления в силу, основной первым; отменённые тоже входят |
| `invalidated` | `doc_id` отменённых документов |
| `status_at` | для каждой даты из `as_of_dates`: `active`, `partially_suspended`, `terminated`, `not_yet_in_force`, `unknown` |
| `terms_at` | для каждой даты — действующие значения условий: `{условие: значение}` |
| `rates_at` | для каждой даты — действующие ставки |

`as_of_dates: [2026-10-30, 2027-02-01]`.

## Кластеры (`clusters`)

`category` — ключ категории предмета, `members` — номера договоров (`contract_number`).

## Ловушки (`traps`)

Для каждой ловушки из списка T1–T16 (список ловушек — в эталоне реального пакета, вне репозитория) — одна или несколько записей. Виды проверок:

| `kind` | `expected` |
|---|---|
| `issue_present` | `{"code": "<код>"}` у цепочки `contract_number` |
| `status_is` | `{"as_of": "YYYY-MM-DD", "status": "<статус>"}` |
| `order_is` | `{"order": [doc_id, ...]}` |
| `excluded_from_consolidation` | `{"doc_id": "<id>"}` |
| `term_value_at` | `{"as_of": "...", "term": "<условие>", "value": "<значение>"}` |
| `rate_planned` | `{"as_of": "...", "label": "...", "amount": "..."}` |
| `doc_kind_is` | `{"doc_id": "...", "kind": "..."}` |
| `normalized_number` | `{"doc_id": "...", "number": "..."}` |

Коды проблем, которые выдаёт система: `parent_date_conflict`, `title_body_mismatch`, `missing_main`, `draft_main`, `invalidated`, `date_from_references`, `order_by_number`, `target_missing`, `party_name_mismatch`, `no_base`, `number_conflict`, `doc_date_conflict`, `parent_number_conflict`, `duplicate_main`, `unlinked`.

## Расшифровка сканов (`scans`)

Для указанных страниц — текст, как он напечатан на изображении: построчно, без исправлений. Рукописное, что не читается, — `[неразборчиво]`.

## Вопросы для чата (`data/golden/chat_questions.yaml`)

Список из 15 записей: `id`, `question`, `expected_facts` (строки и числа, которые обязаны быть в ответе), `unanswerable` (`true`, если ответа в документах нет), `follow_up_of` (`id` вопроса, к которому это уточнение, или `null`). Состав: 5 фактов, 3 об истории условий, 2 сравнения, 2 уточнения с опорой на предыдущий вопрос, 3 вопроса без ответа в документах.

## Пример (вымышленный)

```yaml
documents:
  - file: "Пакет/ДС1.pdf"
    doc_id: "abc123def456"
    kind: supplement
    number: {value: "D990000002-01", page: 1, quote: "Дополнительное соглашение № D990000002-01"}
    parent_number: {value: "D990000001-01", page: 1, quote: "к Договору № D990000001-01 от «21» января 2021 г."}
    parent_date: {value: "2021-01-21", page: 1, quote: "к Договору № D990000001-01 от «21» января 2021 г."}
    effective_from: {value: "2026-07-01", page: 1, quote: "вступает в силу с 01.07.2026"}
    rates:
      - {label: "Тариф А", amount: "700", vat: excluded, valid_from: 2026-07-01, page: 1, quote: "Тариф А — 700 рублей без НДС"}
    ops:
      - {op: replace_clause, target: "3.1", page: 1, quote: "Изложить п. 3.1 Договора в следующей редакции"}
```
