# Архитектура

## Задача

На вход — пакет договоров и дополнительных соглашений: PDF с текстовым слоем, сканы, смешанные PDF, DOCX и изображения. На выходе:

- отчёт в Markdown: кластеры, различия внутри кластеров, цепочки документов, эволюция условий, действующие условия на дату, отказы и противоречия, Reflection;
- база знаний с проверенными значениями и ссылками на источник;
- чат по базе знаний с памятью диалога;
- трасса каждого шага агента (`trace.jsonl`).

## Принципы

1. **Код — для предсказуемого, агент — для решений.** Чтение файлов, OCR, регулярные выражения, сборка цепочек, свёртка и проверки — детерминированный код. LLM понимает текст, а агент решает исключения: перечитать плохой скан, что делать с противоречием, когда работа закончена.
2. **Шлюз проверок нельзя обойти.** Значение попадает в базу знаний, только если его дословная цитата есть на странице, значение следует из цитаты, формат верный, уверенность OCR выше порога и поле не вымарано. Иначе — отказ с причиной в отчёте.
3. **Всё спорное — за интерфейсом и выбирается замером:** OCR-движок (E1), свёртка кодом или LLM (E3), оркестрация (E4). Результаты — в `docs/experiments/`. Модель — параметр запуска: её выбирает заказчик, замер E2 оставлен как инструмент для такого выбора.
4. **Документы не покидают машину.** LLM работает локально через Ollama, OCR — локально.
5. **Текст документа — данные, а не инструкции.** Инструменты агента только читают, запись идёт только через шлюз.

## Граф агента (вариант B, гибрид)

```
ingest      код: опись, чтение всех файлов (текстовый слой или OCR), разбор заголовков
planner     LLM: план-чек-лист по описи
executor    LLM: «Мысль» → вызов инструментов  ⇄  tools (с лимитами и защитой от повторов)
reflector   код: чек-лист плана; LLM: оценка цели → при пробелах обратно к executor (≤ 2 кругов)
reporter    код: подстраховка недоделанных шагов, отчёт, проверка утверждений, база знаний
```

Инструменты агента: `list_inputs`, `read_document`, `rerecognize`, `analyze_document`, `build_chains`, `consolidate`, `cluster_and_compare`, `record_decision`, `write_report`. Ошибка инструмента не роняет запуск: агент получает ответ `{"status": "error", "error_type": ..., "hint": ...}` и выбирает обходной путь.

Варианты для замера E4: A — тот же порядок шагов кодом без агента; C — полный агент, сам читает каждый файл; S — один вызов LLM на папку, без шлюза.

## Модули

| Модуль | Что делает |
|---|---|
| `ingest/` | опись файлов, чтение по страницам (текст, OCR, пусто), нормализация текста, нарезка на пункты |
| `ocr/` | PaddleOCR PP-OCRv5 через RapidOCR/ONNX (победитель E1) и Tesseract; ориентация страницы — Tesseract OSD, затем геометрия строк; порядок чтения по строкам |
| `parsing/` | номера документов, даты, суммы, разбор заголовка регулярными выражениями |
| `understand/` | извлечение по группам полей через LLM, пакеты пунктов по бюджету токенов |
| `gate/` | проверки и статусы значений: `accepted`, `rejected`, `conflict`, `redacted`, `absent` |
| `assemble/` | цепочки договоров и свёртка условий на дату |
| `analyze/` | кластеры по предмету и признакам, различия внутри кластера |
| `report/` | шаблон отчёта и проверка утверждений LLM на ссылки |
| `kb/` | база знаний: JSON и SQLite FTS5 с лемматизацией |
| `agent/` | граф LangGraph, инструменты, трасса, лимиты, варианты оркестрации |
| `chat/` | чат над базой знаний, память — checkpointer LangGraph в SQLite |
| `llm/` | клиенты Ollama и OpenAI-совместимого сервера, кэш ответов (record/replay; ключ — запрос и параметры генерации, оборванные ответы не хранятся), структурированные ответы с повтором |
| `eval/` | эталон, метрики, ловушки, замеры E1–E4, оценка чата |

## Свёртка

Документы цепочки применяются по дате вступления в силу из текста, а не по имени файла. Правила:

- отменённое соглашение остаётся в хронологии, но не применяется;
- изложение документа в новой редакции заменяет базу;
- соглашение без операций замены дополняет условия договора;
- истёкшее соглашение не применяется после даты окончания;
- ставки с будущей датой помечаются «запланировано»;
- прекращение части обязательств — это не расторжение.

## Проверка качества

- юнит-тесты без LLM;
- сценарии агента на записанных ответах модели;
- внедрение ошибок;
- эталон по реальным документам (вне репозитория) и отложенный синтетический набор в `synthetic/`;
- замеры E1–E4 по правилам, записанным до замера.
